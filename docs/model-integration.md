# Model boundary and live verification

The default application mode is manual. Browser speech recognition can transcribe an update where supported, but it is not a verified Bedrock call. The typed progress status remains explicit and a separate user confirmation completes a step.

The optional adapter uses the AWS SDK Converse API. It receives the user's text, current step IDs/titles/statuses and phase; it returns a constrained report, interrupt, resume or clarification proposal. Unknown actions/IDs and extra fields are rejected. Evidence is copied from the actual input, not generated by the model. The adapter cannot call confirm, correct, reset or arbitrary tools. A proposed interpretation must be reviewed before the browser executes the relevant MCP tool.

Completion proposals still require the separate confirmation control. No model verdict is accepted as proof of physical completion.

The tests inject provider responses and failures explicitly. They verify parsing, action/ID boundaries and no-state-change failure behavior. They do not measure real model accuracy, instruction-injection resistance, latency, cost or availability. The 20 held-out conversational evaluation target remains unmeasured.

Live gate: configure only an authorized account/role, region and real supported model ID; approve paid usage; enable Bedrock mode; execute the frozen utterance set and record actual request IDs, usage, pass/failure counts and latency without secrets. Test negative and contradictory statements, prompt injection, timeout and invalid output. Report all failures; do not convert fixture results into provider claims.

Primary references: [AWS Converse](https://docs.aws.amazon.com/bedrock/latest/userguide/conversation-inference-call.html), [official MCP TypeScript SDK](https://github.com/modelcontextprotocol/typescript-sdk). The pinned SDK supports MCP 2025-11-25; the browser and server use Streamable HTTP with actual local tool calls.
